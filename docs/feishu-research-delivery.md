# 阶跃 · 飞书研究推送开发与验收

## 保存输入的本地简报回放（不发送）

`scripts/preview_research_brief.py` 只回放已完成的 `research_automation_batches`。默认使用原始 SQLite `mode=ro`，校验保存结果的 SHA256 和分类/数据日/策略版本绑定；不初始化常规仓库、不恢复 outbox、不采集、不准备/授权/发布、不修改自动化或旧冻结记录。历史过期批次可供本地研究，但不会因此获得正式发布资格。

```powershell
# 使用实际数据库路径和已核对的批次ID；输出目录须已存在，文件必须是新文件。
.venv/Scripts/python.exe scripts/preview_research_brief.py --db "ABS_DB_PATH" --batch-id "SAVED_BATCH_ID" --top-n 5 --title "保存输入研究简报" --output-json "ABS_NEW_PREVIEW_JSON" --output-html "ABS_NEW_PREVIEW_HTML"
```

只有显式指定的输出文件会创建（不覆盖既有文件；仓库内只允许 `.superpowers` 验收目录，不能写入产品源文件）。JSON/HTML 均标识“本地预览、未发送、非正式发布”，不创建假的正式报告/群/投递身份。HTML 对全部动态内容转义，无远程脚本/字体/资源；它不是 React 页面或飞书实际卡片的视觉验收替代品。

可选保存证据增强：`--evidence-dir "ABS_SAVED_EVIDENCE_ROOT"` 读取保存的精确当日全量 `daily`/`stock_basic` 捕获，跳过逐股历史日线；`--reference-manifest "ABS_REFERENCE_MANIFEST"` 验证并复用事先捕获的名称/行业与 ETF 名称；`--background-manifest "ABS_BACKGROUND_MANIFEST"` 验证原批次 ID/输入哈希、捕获 SHA、元数据、主体和日期，再复用 `candidate_background`。不信任清单里可变的 `background` 附件。所有文件路径必须位于对应证据根/清单目录内；构建市场背景仍使用既有 `_read`/`build_market_context` 与原实际观测时间，不绕过生产 `load_market_context`/enricher 的当日门禁。跨策略比较使用该数据日全部通过哈希校验的已完成批次、同一 Top N 范围；只代表已完成样本重合，不代表全市场共识。零条符合条件的新闻/公告不是供应商失败，也不能证明没有相关新闻或风险。

数据业务日、保存捕获的实际观测时间和本次真实生成时间分别保留。跨午夜只回放已有捕获，不能抓取今日基本面/新闻后贴成昨日观测。页面显示历史日期及“非当日行情”；板块的已观测成分等权均值不是官方板块指数；旧记录缺少日期时明确显示未知，不从生成时间倒推。

React 预览的观测时间只在正文外展示首末范围与时间点数量，逐条原始来源放入默认折叠的核验详情，避免大量捕获时间挤占正文。历史板块支持排名容器和每个排名行的 `asOf/source/definition`，行字段优先；已展示行日期不一致或部分未知会如实标注，不借用报告生成日。背景新闻/公告即使外层捕获业务日正确，每条线索仍必须有原同业务日且不晚于真实生成时刻的观测时间，并通过原主体、近三日披露窗口、证据种类和供应商链接契约；空列表保持合法。

`screening_snapshot` 派生的 PE/PB 没有独立供应商观测时间时，只能与背景捕获所绑定的原批次同代码候选值和业务日逐项一致；不为它补造观测时间。独立供应商背景仍须保留并通过原始时间戳检查。

只有 `--use-model` 显式允许模型。它沿用配置中的模型路由、`ExplanationService`、完整冻结输入/提示版本/生成预算 once-key、45秒/4096输出token（新简报；旧解释仍1800）和每日20次尝试账本；复用既有结果，失败尝试也占额度，不增加重试。为避免建表与 outbox 恢复，窄 ledger adapter 仅借用现有 `reserve_llm/finish_llm/atomic`，SQLite 授权器拒绝其他表读写及建表。该选项不再是全库只读：仅既有 `research_delivery_llm_attempts` 可写，仍绝不发送。真实验收额外调用上限由主控另行控制，不能把每日20次理解为本轮许可。

验收前后应以只读 SQL 比较 outbox 的 `id/status/attempt_count`（不仅比较总数），另核对正式报告和 release 数量，确保无新增正式记录；界面桌面/手机截图、离线 HTML 截图和模型效果分别验证。模型文字与条件观察仍需人工复核，不承诺收益。

## 目标和当前边界

面向自己与熟悉的研究伙伴，按策略建立独立群：共享采集数据，各自计算、解释、审核与投递。系统提供研究线索和风险信息，不连接自动交易，不把规则评分、模型置信度或选股结果当成盈利概率。

设计：[多群订阅设计](superpowers/specs/2026-10-13-feishu-strategy-subscriptions-design.md)；分期：[开发路线](superpowers/plans/2026-10-13-feishu-push-roadmap.md)。

2026-10-15 更新：多群设置、只写 Webhook、历史研究草稿，以及本机原生持久工作进程、当日数据采集、冻结报告和正式飞书投递链路已经实现。总开关默认暂停；保存新群不会自动授权发送。十种 A 股策略、ETF、市场雷达、公告风险支持当日生产，O01 系统状态仍未接入。配置成功、工作进程在线、当天数据通过和飞书接收是四件不同的事；实现完成不等于已通过真实上线验收。现有手动选股/单群通知默认行为保留。

## 页面配置：每类一个群

入口：`设置 → 通知渠道 → 飞书多群订阅`（默认）。旧版字段和测试独立收进“其他渠道与旧版通知”，不再与多群表单混排。需要开启现有管理员登录并登录；保存凭据要求 HTTPS 或本机回环地址。两套配置不会互相覆盖或回退。

1. 在飞书为每个研究群添加独立的自定义机器人。建议先建 T00 联调群；其他群按 S01—S11、R01、R02、O01 分别创建。不要把地址或密钥发到聊天、Git 或共享表格。
2. 点击“新增群订阅”，或直接点击尚未配置的内容类别。这里连接已存在的飞书群，不会替你在飞书创建群。
3. 在同一个表单内选择内容类别、填写飞书群名称、独立 Webhook、可选签名和关键词（建议“阶跃”）；也可选择“使用已保存的群连接”。不需要 App ID、App Secret 或 Chat ID。
4. 设置 Top N、模型作用和计划时间，点击一次“保存群订阅”。新群连接和内容绑定作为同一事务提交，默认暂停；列表展示对应群名和保存时间。成功后密钥从表单清空，不回显。保存不会计算或发送，也不会因为总开关已开而自动将新群加入启用选择。
5. 如需验证某群，在“群连接”单独启用目标，点击该行“测试连接”，核对群名与固定测试正文，再点“确认发送这一条”。每次只向此群发送一条非金融测试。保存和历史预览不发送；启用已有订阅若满足总开关、计划和数据条件，则可能进入真实自动投递。T00 或不需要订阅内容的备用群可使用“群连接 → 高级：只登记测试或备用群”。
6. “研究预览”选择订阅和实际已保存的策略运行；默认不调用模型。勾选“本次使用 AI 解释”才可能调用已配置模型。草稿保留原始风险、数据日期缺口和排序；LLM 不改名单，不转成当日荐股报告。点击“投递记录”核对单群结果。
7. 在页面上方“自动推送总开关”逐项核对订阅、群名、类别与北京时间，再点击“启用所选群”。该操作启用所选订阅，其他群状态不变；取消勾选不等于暂停已启用群。单群使用“暂停该订阅”，全部停止使用“暂停全部自动推送”；暂停不能撤回已经提交给飞书的在途请求。
8. “运行今天”是真实采集、按订阅配置调用模型和发送，不是测试。它只让当前已启用订阅不必等计划时间，不绕过 15:30—22:30、交易日和数据门禁。“已受理”仅表示排队回执，不是消息接收回执。响应丢失时保留原请求编号，只刷新运行状态并核对各群，不能盲目生成新编号重发。

多群入口不显示旧版“保存配置”和“发送测试”，只使用当前表单的保存按钮。“放弃未保存草稿”只清空多群草稿。旧版入口保留原有通用保存；切换入口保留未保存内容，离页仍提示。已有订阅点击分类直接编辑，无需再创建。

“研究预览”的保存列表同时展示正式报告与历史草稿。正式报告须精确关联 `kind=formal`、报告 ID、目标 ID 和目标版本一致的唯一投递记录；只有该记录为 `sent` 才显示“飞书已接收”，不等于伙伴已读。报告自身状态或数据就绪不代表已发送；缺少或冲突的身份保持未确认，不提供批准/发送入口，历史草稿仍不可正式发布。此列表使用已读取的投递记录，不随自动化状态轮询刷新；需核对最新接收结果时使用“重新读取”。ETF、雷达、公告的模型模式不再依赖历史预览能力，但仍受全局模型可用性约束，O01 保持禁用；保存模式不会调用模型或发送。自动化作业的 `retry_wait` 显示为“等待数据重试”，不表示已发送，也不新增页面重试操作。

已有群的高级连接维护仍采用名称/用途与连接分步编辑，避免覆盖草稿；修改签名或关键词须重新填写当前 Webhook。日常新增不再走这条三次保存流程。

### 一次保存与断网核对

`POST /api/v1/research-delivery/setups` 接受稳定 `request_id`、订阅参数及二选一的新群连接/已有群 ID 与版本。数据库一次提交目标、订阅和保存回执；明确信息校验失败不留下半个群。相同编号和内容重提返回原记录，不重复新建；改动内容复用编号返回 409。旧 API 保留兼容。

若保存响应丢失，表单显示“结果尚未确认”和保存编号，锁定输入；先点“核对是否已保存”，只读调用 `GET /setups/{request_id}`。暂未查到不代表在途请求已失败；可以稍后核对，或明确点击“用原编号重试保存”，仍提交同一份内容。不会自动重试写入，也不会触发消息或模型。关闭表单会清空内存中的密钥和待核对载荷，重新进入后先检查订阅列表。

原编号重试即使被明确拒绝（例如会话过期），也不能证明首次保存失败。页面继续保留未知状态、锁定内容和原编号，恢复登录或服务后再次核对；仅首次请求明确拒绝时才提示“未保存”并允许直接修改。

新增 `research_delivery_setup_receipts` 追加表仅存请求摘要、目标/订阅 ID 和时间；不存明文密钥。现有 vault 的文件和 SQLite 不构成跨资源事务：极端数据库故障可能留下没有记录引用的受保护文件，但不出现可见的半个群；不会自动删除用户凭据文件。

### 当日运行与数据范围

北京时间 15:30 开始跑策略并整合数据（A 股 15:00 收盘后留 30 分钟给日线数据落定）；随后按固定顺序**一个一个做研判并推送、完成即发**，不按固定时段等待，因此到达时间取决于实际耗时而非整点。数据或模型未就绪则顺延（该群重试，不阻塞后面的群），但 22:30 为硬截止（不含 22:30），不越过午夜、不补发历史。工作进程与心跳独立运行；网页关闭不影响服务进程，但 localhost 应用/服务、电脑和网络必须保持运行。页面“工作进程离线”不等于总开关已暂停；“当天数据未通过”也不等于功能没接通。

第一版 A 股采用 `restricted_complete_core_metric_eligible_universe`：只纳入必需核心数值齐备的受限样本，不是全市场排名。行情响应覆盖率仍以独立股票池为分母并要求至少 95%；排除样本有审计证据，不把缺数据改称“没有候选”。十策略复用原规则；各策略技术计算最多 100 只，页面 Top N 最多 20，未技术评估者不是“不符合”。`independent_universe_count/eligible_count` 是股票数量，`required_count/valid_count` 是必需字段单元数，不能把 35,343 个字段单元写成 35,343 只股票。

ETF 使用配置资产池（含防御资产）的一年历史和当日有效报价；缺资产则阻断，不缩池冒充原策略，也不展示回测收益承诺。雷达仅使用有当日日期和来源的主题/宽度事实，快照宽度不是全市场事实。公告是配置股票/当日候选的有限范围最近三天公开元数据，最多扫描 30 家，展示已扫/未扫/失败；未发现记录不等于公司无风险，不是每 15 分钟实时公告扫描器。

| --- | --- |
| Tushare `trade_cal`、`stock_basic` | 真实交易日与独立上市股票池；凭据缺失、权限不足、日期/身份异常则阻断 |
| Tushare `daily`、`daily_basic` | 当日报价与 TTM PE/PB/市值等；保留原始响应，逐表日期和单位校验；不以静态 PE 补 TTM |
| Tushare 历史日线、`adj_factor` | 技术样本前复权与至少 61 根有效观测；需分别具备端点权限，权限/额度不足不是无候选 |

数据源权限和额度取决于实际账号，配置 Key 不代表已获得所有端点权限。已知超时、限流、请求失败以及行情覆盖不足允许至多三次采集尝试、间隔至少十分钟；权限、日期、身份、关键缺失等完整性失败不热重试。模型只能解释冻结事实，不改排序、不新增数字；超时、不支持、无证据或校验失败会明确回退事实模板。模型回退不能补齐缺失数据，也不绕过数据门禁。飞书 `delivery_unknown` 不自动重发；正式消息最终序列化后执行内部 16 KiB 预算，超限明确阻断，不偷偷截断候选名单。

研究解释使用现有主模型配置；仅 DeepSeek 在未显式配置 `extra_body.thinking` 或 `reasoning_effort` 时默认关闭思考，避免有限输出预算耗在推理中。显式设置原样保留，其他供应商和全局模型配置不变。历史草稿保持 `research-explain-v3` 与1800输出token，每候选至多一条简短、无数字、有引用的推断。新正式简报为4096输出token；被禁用的交易/风险承诺措辞即使是否定句也不能出现。单请求、45秒超时、零重试、每日最多20次不变；旧冻结报告和投递不会因此重算或补发。仅保留安全枚举 finish_reason；明确 `length` 才记为 `model_output_truncated` 并保留用量，不抢救部分JSON、不发修复请求。没有结束原因的旧 `invalid_model_output` 不能据token数追认截断。

### 正式简报与冻结卡片

新准备的当日正式文档追加 `format_version="research-brief-v1"`、`title`、`brief_input` 和 `card_payload`；历史文档缺少版本时仍按原文本发送。简报先展示研究判断，再按原 Top N 顺序分块展示策略指标、具体风险、可用背景与矛盾，最后给出后续核验/失效条件。每个候选最多三个关键指标，技术、估值、股息等按当前策略取舍，背景指标与通用指标共用额度，不再额外堆叠规则分和背景面板。模型解释中的数值占位引用也不能扩大该额度；完整事实仍可支持无数字的解释。ETF动量从原小数比例转为百分比显示，明确冻结交易日窗口，权重附名称且不因展示切片重新归一；无法解析的名称明确未知。公告仍先切记录 Top N 再按发行人去重，不改变源记录顺序。

`build_brief_input(envelope, detail, source)` 只投影冻结来源公共字段，并复用本地策略注册表的中文名称；每条事实含 `id/domain/subject/key/value/unit/source/date/display`，财报另保留披露日；不请求市场数据、不改策略/分数/风险。行业上下文只含候选所属行业和各两个领涨/滞后行业；完整原表仍在冻结来源快照。新 v4 的 `brief_prompt_input` 调用 `signal_prompt_input`，只投影可选信号和其支持事实，省去事实中重复的 id/display；once-key仍绑定完整输入、提示版本及4096输出预算。48,000字符输入上限不变，超限明确回退。

已知快照PE/PB不会被原有笼统估值缺失标签覆盖，只有市值则不代表PE/PB已知。部分财务字段可用不代表该领域完整。新闻只作线索，公告只作标题元数据；行业是观测成分等权均值，非行业指数，也不自动证明多数成分上涨。通用评估缺口不再逐股重复，只有影响当前策略结论的缺口在末尾汇总一次，子集缺口标明对应候选，具体PB偏高、换手偏高、超买等风险仍留在各候选旁。覆盖分母/比例、核心完整数量、扫描公司数量及警告审计集中保留在 `detail.audit`，不占用正文。原指标、评分与风险仍在冻结信封/来源中，不改成“已核实低风险”。

新正式提示词 `research-brief-select-v4` 与 `strategy.expression_version=4` 使用证据约束选材，不称为开放式自主研究。程序从完整冻结事实生成有界 `signal_catalog`；模型比较依据并选择重点，仅返回 `summary/cross_signals` 及逐候选 `rationale/watch/invalidation` 的信号 ID 数组，每个公开 section 最多一段。候选身份与顺序改变整份拒绝，未知 ID、错角色、跨候选 ID 局部拒绝；禁止自由改写正文。规范化段落为原五字段加 `signal_id`，服务、正式准备、CLI 和冻结重放均重建同一目录、逐字段精确匹配，修改正文或引用不能绕过重验。仅保存白名单诊断，无自动修复请求或额外重试。

目录按实际正、负、零区分盈利、现金流、股息与资金方向；分红实施与盈利回落、估值与负增长、价格与净流出等张力必须同时引用相应事实。负经营现金流仅提示按报告期核验，不直接判断财务恶化。所属行业与个股当日资金关系要求行业绑定、行业均值和个股净额三者齐全，且三条事实日期均等于业务日；历史归属可保留为冻结背景，但不得支撑这条当前观察，日期缺失、过期或未来日期均拒绝，保留未来核验项。仅有 PE 不会产生已观察行业负反馈或资金流入信号。市场广度、行业均值与上涨/下跌家数关系、Top N 重合数量及并列主体均由程序计算，最高重合仅比较本组候选。缺领域时只提供不暗示当前状态的未来核验模板。正文不新增数值指标，既有三指标额度与原始具体风险保留；候选栏目直接展示目录正文，避免“待观察：观察：”重复前缀。

历史无标记/v2/v3 保持原校验与渲染；v3 仍只兼容精确五字段单段对象和最多八段的有界数组，不能把旧自由正文当作 v4 选材复用。v4 不证明任意自然语言为真，只公开程序目录文本；模型负责重点选择，事实质量仍依赖冻结来源与生产者证据门禁，需人工复核。冻结报告新增 `model_adoption`，分别记录 summary、candidate_rationale_count、cross_signals、watch/invalidation、watch_only 与 core_complete；裁剪后按实际公开采用量统计。缺 summary 或任一候选 rationale 不标核心研判成功，已有部分采用记 `fallback/incomplete_core_explanation`；完全未采用记 `fallback/no_effective_model_paragraphs`。诊断保留逐角色 missing_core，程序继续补逐候选解读和观察项。

同日榜单重合合并展示中文策略名称，原ID留在冻结事实；范围只说明一次，不当作独立概率票。已知行业附在名称旁，未知或过期行业不补写；行业集中度只数已知部分。缺口子集优先实名，同名则附代码。原“行业排名数据缺失”仅在同日Tushare分类/等权定义/有效观测覆盖均可验证时改为原排名源不可用且已有观测均值，真正概念缺口与原始警告保留。历史板块日期先校验完整ISO日期/时间戳，非法后缀显示未知。

`render_brief(title, envelope, detail, llm, brief_input)` 同时生成可读正文与 `interactive` 卡片，两者正文完全一致，关键词必须出现在可见正文。模型once-key包含格式/提示词版本和完整冻结公共输入。最终序列化载荷上限16 KiB；超长时先压缩可选模型扩展与背景数值（完整内容仍在冻结文档），不丢候选、具体风险、矛盾与条件观察；仍超限则明确阻断，不偷偷截断。准备与投递都使用同一版本化渲染，投递额外复验完整冻结文档、批准卡片、载荷哈希与原有租约/配置/时窗，再执行一次发送；不会在发送时重新取数或重新解释。未知送达结果仍不换格式重发。

### 安全与故障处理

- 保存出现 403 时按具体代码处理：`auth_required` 是管理员登录未开启；`cross_origin` 是来源缺失/不匹配或跨站请求，改密码不能解决；`secure_transport_required` 是非 HTTPS 且非真正本机连接。未知 403 不再一概提示管理员权限不足。服务端只记校验布尔结果，不记录 Cookie、Webhook、签名或原始来源/Referer 内容。不要为解决此提示关闭管理员登录或全部取消来源检查。

- Windows 凭据由当前服务账号的 DPAPI 保护；Linux 凭据目录 0700、文件 0600，仅服务账号可读（不是磁盘级加密）。普通 DB 只有引用和指纹。备份需同时包含 DB 和受保护的凭据目录；跨主机/服务账号迁移时应重新录入连接，不能只复制 Windows 密文。
- 同一 Webhook 不允许登记到两个目标；多个订阅可以显式选择同一群，但一类一群时应选择各自独立群。
- 同地址空签名保留旧值；更换已签名地址必须同时录入新签名。当前没有页面清除既存签名的功能；不要以留空当作清除。改群/凭据/订阅会增加版本，停止旧的待发任务。
- 409 版本冲突时，取消当前编辑、重新读取并核对后再改；不自动覆盖其他会话的修改。网络结果不明也先读取，不盲目重提。
- `sent` 仅表示飞书业务回执确认接收；`delivery_unknown` 表示可能已经发出，先到群里核对，不自动重发或改发文本。未知状态暂不提供页面补发/人工消账；保留审计，不能通过删除记录恢复按钮。
- 旧版通知测试仍属于原有单群链路，其发送/降级语义未被此处替换。使用多群时在本工作区逐目标配置和测试，不在全局地址中拼接多个 URL。
- 历史运行缺少完整数据验收，批准与发送 API 均拒绝正式发布。不能通过勾选“已核验”或修改浏览器参数绕过。

## 为什么先做数据门禁

- 保存时间不等于行情日期：检查每只股票声明必需的字段业务日期，而不是文件修改时间或整表最大日期。
- 没取到数据不等于没有符合策略的股票：先验收完整股票池，再允许输出“本轮无候选”。
- 快照筛选通过后只对前 N 个候选做技术计算；剩余股票必须标为“未评估”，不能写成“未通过”。
- PE、PB、成交额及市值必须口径可辨。元/千元/万元混用，或静态 PE 冒充 TTM，都会改变策略结果。
- 日线先检查真实 OHLC、成交量、复权和日期，再算指标；不允许用收盘价补成缺失的开高低后声称完整。

## 数据验收状态与发布权限分开

| 状态 | 含义 | 行为 |
| --- | --- | --- |
| ready | 已声明的必需数据验收通过，无可选缺口 | 仍然只是数据状态，不自动获得发布权限 |
| degraded | 必需数据通过，可选板块、资讯等证据缺失 | 展示缺口，不包装为完整投研 |
| blocked | 日历、股票池、日期、原始数据或关键证据不满足 | 不返回可供发布的候选结果 |

历史/本地只计算预览始终 `publish_allowed=False`。当日原生发布是另一条冻结批次链路，已检查群目标、配置/授权版本、有效租约、允许时段、暂停状态、数据版本与发送幂等；不能把旧草稿改标记后直接发布。

### 本地命令

在项目根目录使用专属虚拟环境：

```powershell

.\.venv\Scripts\python.exe scripts/research_delivery_preview.py preview --bundle "已验收输入包.json" --strategy dual_low --technical-limit 100

`catalog` 返回真实十策略清单；`preview` 仅从本地包读取数据，不下载行情。输出包含业务日期、数据状态、分层覆盖计数/代码、规则与风控后的结果，并固定 `preview_only=true`、`publish_allowed=false`。成功或降级退出码为 0；数据阻断、文件或格式错误为 2。没有数据包时只运行 `catalog` 或 `--help`，不要为了通过检查手工伪造来源字段。

版本 1 数据包顶层必须且只能包含 `schema_version`（整数 1）、`trade_date`（YYYY-MM-DD）、`calendar_verified`、`universe_verified`（真布尔值）、`universe`（代码列表）、`snapshot`、`daily_histories`（代码到日线对象映射，非日线策略可用空对象）。每个快照/日线对象固定 `{columns, index, data, attrs}`；`attrs` 仅接受下面约定的来源、日期、单位等元数据。文件上限 20 MiB，拒绝重复 JSON 键、重复列、非有限值和额外配置字段；不支持 pickle、URL 下载或命令执行。

### 采集适配器契约

这是 Python 内部采集适配器契约，不是开放给浏览器任意提交数据后就信任的接口。

快照包含规范六位代码、名称、价格、涨跌幅、成交额、市值、PE、PB、换手率、量比，以及策略要求的字段。外部独立确认的股票池应与快照唯一代码集合一致。逐字段日期映射指向各自原始表的业务日期列；不允许把行情表日期冒充估值表日期。

采集器还需声明来源、证据标识、单位与估值口径：价格为元/股，成交额/市值为元，涨跌幅/换手率为百分点，估值与量比为无量纲。严格预览要求 TTM PE。元数据声明不是来源真实性证明；正式接入必须保留供应商原始响应和转换证据，不能手工补几个“有效”标记让旧缓存过关。

快照 `attrs` 的必需键是 `snapshot_source`、`evidence_id`、`units_profile="cn_equity_cny_v1"`、`pe_ratio_basis="ttm"`、`field_trade_date_columns`（字段名到该字段日期列的映射）。日线必需键是 `code`、`daily_source`、`evidence_id`、`price_adjustment="forward"`、`volume_unit="shares"`。来源声明必须对应实际采集/转换结果，不能把静态 PE 更名为 TTM，也不能给未复权价格直接贴前复权标签。

技术候选输入为按代码绑定的原始前复权日线，要求至少 61 根有效有序记录、最新日期为目标交易日、成交量口径为股，且末日复权收盘与快照价格不存在明显比例冲突。61 根是本期最低计算门槛，不等于 MACD 完全收敛；本期也没有证明整个历史区间交易所日历连续性，不适用于宣称已完成严格回测。

只计算路径不使用模型、不补抓外部数据、不调用 DSA 扩展、远程后处理器或通知器。保留现有规则、风控和本地评分卡，不另造一套选股公式。缺板块热度的策略明确沿用现有中性值并标记降级，不偷偷改权重。

### Tushare 原始表离线诊断（W1 快照子集）

内部纯 Python 接口 `src.services.research_delivery.tushare_snapshot.assess_tushare_snapshot(daily, daily_basic, stock_basic, *, trade_date, universe, calendar_verified, universe_verified)` 仅验收调用方已捕获的三个 DataFrame，返回 `ReadinessResult`。没有新 CLI/API、采集、LLM、调度或推送入口；独立股票池和日历的布尔值是调用方声明，不是本接口自动验证的结论。

先检查全部来源的列、唯一身份、跨表六位代码一致性和支持的标量类型，再投影到独立声明的股票池。多余股票只因明确 scope 被排除，来源重复或异常对象不能借此被隐藏。复用真实 Tushare 转换函数，严格模式的外连接保留缺报价股票已有的每日指标/名称，再按完整股票池重建行；每只股票的九个 `CORE_FIELDS` 均进入分母。缺失/非法数值成为字段阻断，不进行前置价格/策略筛选，不因缺行情缩小股票池。普通模式仍左连接并过滤无效价格；严格模式保留原报价顺序，按原表顺序追加指标/参考独有股票，诊断结果则按调用方股票池顺序验收。

官方字段依据（控制方于 2026-10-13 核对公开文档，未调用真实行情）：[日线 daily](https://tushare.pro/document/2?doc_id=27) 的 `amount` 为千元、价格未复权，停牌可能无日线；[每日指标 daily_basic](https://tushare.pro/document/2?doc_id=32) 包含自己的 `trade_date`，`pe` 与 `pe_ttm` 不同，`total_mv/circ_mv` 为万元；[股票列表 stock_basic](https://tushare.pro/document/2?doc_id=25) 有 `name/symbol/list_status/list_date`，但没有 `trade_date`。转换仅用 `pe_ttm`，成交额乘 1000、市值乘 10000，分别保存行情/指标日期；缺 TTM 不回退静态 PE，负 TTM 保留为真实数值观察而不是改成缺失或正值。

`name` 没有可靠业务日期，所有正常数值齐备的当前样例仍是 `blocked`；`list_date`、采集时刻、请求日期或其他表日期均不补作名称日期。缺报价也不自动解释为“确认停牌”：独立上市状态、停复牌、交易日证据与原始响应持久化仍待 W1 后续完成，历史连续性/复权验收和 W2—W6 也不属于本子集。旧缓存不会新增证据 ID 或日历/股票池确认，不能通过补标签转为已验收证据。

诊断为实际 scope 内的原始记录生成 SHA-256：包含端点标签、实际使用的原始列/身份（含已有 symbol）、明确类型的标量和规范化版本；排除 index、attrs、表行顺序、scope 外记录和未使用的静态 PE 等列。None、NaN、布尔、非有限浮点有稳定编码，但数值验收仍拒绝缺失、布尔或非有限观察；数值列内的 date/datetime 也拒绝转换为纳秒整数，业务日期列仍接受合法日期。时长标量不属于诊断支持的原始类型，固定结构错误拒绝；直接调用共享转换时，时长数值也保持 NaN 而非纳秒。任意对象不以 str/repr 序列化。哈希只证明输入内容身份，不证明供应商真实性，也不保存原始响应。调用方应保管完整捕获证据；本接口不返回可发布的候选、不授权发布。

类型/结构失败固定抛出 `ValueError` 代码：`tushare_request_invalid`、`tushare_universe_invalid`、`tushare_source_schema_invalid`、`tushare_source_scalar_invalid`；不拼接原始数据或异常对象。数值缺失、错日期、未知日历/股票池及单位契约问题则进入既有 readiness 阻断清单。

兼容边界：TTM-only 保证适用于本批修正后新采集/转换的 Tushare 表，不是所有历史手动缓存。原手动流程仍可按既有规则读取旧缓存，其中 PE 可能保持旧口径；旧记录不会被重命名或升级为 TTM 证据，严格验收会拒绝其缺失的口径、日期或来源凭据。

## 显式历史修订版（操作员 CLI）

修订版不是补跑自动化，也不延长原正式发布窗口。仅对指定业务日当前启用、原正式 outbox 已 `sent` 的完整订阅集合创建新的 publication/release/outbox；原 batch/publication/release/outbox/AutomationJob 均不修改。原 publication 仍为 `prepared` 不代表未发送，必须核对唯一关联的 formal receipt。股票 `source_run_id` 是选股运行编号，原批次以 release.batch_id 为准。

`scripts/revise_research_delivery.py` 提供 `prepare`、`inspect`、`deliver`。每条命令均显式要求 `--db`、`--vault`、`--day`、`--edition`、`--output-dir`；edition 是操作员选择并复用的规范 UUID，输出目录必须是尚不存在的新目录，放在产品源码之外或 `.superpowers` 下。数据库必须已经存在：inspect 使用 SQLite `mode=ro`，prepare/deliver 使用 `mode=rw`，不初始化表、不自动修复回执、不因路径拼错创建数据库。inspect 不加载环境/模型配置、不读取凭据、不更改数据库；输出仅包含白名单清单和可读 HTML。

```
