# 阶跃核心数据与估值可靠性

本轮在现有框架内修复协议、请求配额、结构化排序和估值缺口，不更换页面设计，不购买数据，不启用调度、采集或实盘交易。

## Tushare

筛选的全市场快照和历史日线现在复用项目 HTTP 客户端，以统一 POST 请求体传递 api_name/token/params/fields，不再修改 SDK 私有 URL 属性。不同 SDK 版本可能将接口名拼到 URL 后面，造成 404 和附加 ts_type_name。

筛选保留 TUSHARE_API_URL 优先、TUSHARE_HTTP_URL 次之的地址别名；默认 http://api.tushare.pro，保持项目已有 HTTP 协议。自定义网关必须接受统一 POST 载荷。复权、金额/市值单位及 DataFrame 归一化没有改变。接口权限不足仍需按供应商返回排查，不能等同于 SDK 路径错误。

## TickFlow

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| TICKFLOW_BATCH_SIZE | 5 | 预取希望使用的单批大小 |
| TICKFLOW_MAX_SYMBOLS_PER_REQUEST | 5 | 套餐单次标的上限，约束日线及报价拆批；已保存 100 也会被此值限制 |
| TICKFLOW_REQUESTS_PER_MINUTE | 10 | 同一进程内按 API Key 共享的 60 秒滚动预算 |

按 [官方免费档](https://tickflow.org/pricing/) 保守设置；付费用户可以根据确切权限显式提高上限。没有查询或更改你的账户套餐，没有覆盖用户 .env。设置页提供中英文说明。

预算耗尽立即走现有失败回退，不休眠、不额外增加网络请求。SDK 内部自动重试关闭，避免一次受控调用背后偷偷发送多次请求。服务端返回 429 时负缓存当前窗口。缓存命中不消耗预算，临时管理器不能重置同 Key 的进程预算。

日线使用 SDK 的原始紧凑列数据，由项目本地转换 DataFrame，不触发其自动名称查询。每批不超过 SDK 的 100 标的限制并显式传递批大小，避免一次调用内部再分成多次 HTTP；免费档仍受更小的 5 标的上限。请求时间在预算锁内采样，避免并发插入乱序导致提前释放窗口。

多进程、多容器和其他应用不会共享此预算，必须分摊供应商账户总额度。标的池、分钟等高级接口仍取决于权限；安全拆批不能创造套餐权限。

## 选股结构化输出

- 完整的前置 think 包装通过已有文本辅助函数剥离；不解析思考草稿为最终 JSON，未闭合包装不猜测补全。
- 供应商明确 finish_reason=length/max_tokens/max_output_tokens 时，返回 truncated_response 诊断，而不接受部分候选为完成排序。
- 保留候选白名单、覆盖率、既有模型回退与 max_retries；不提高调用方 max_tokens，不取 reasoning_content 当最终回答。
- Prompt 要求先覆盖全部代码、使用短句和短列表，减少可选背景挤占输出。
- 原有选股页已显示“当前使用因子排序”和“确定性因子”，本轮没有另造一套状态 UI。

上述是假响应验证。旧历史的 invalid_response 未保留完整供应商返回，不能据此宣称此前某次解析失败的全部原因已经证明或所有真实模型已兼容；收费模型的端到端验收需另行确认。

## 持仓完整性契约

持仓、账户、汇总响应追加 `valuation_complete`，通过 `limitations` 表达 `missing_price`、`missing_fx`。正常完整账户计算不变。

- 缺价格保留真实数量和账本成本，不生成假市场价值、收益率或 100% 止损。
- 缺跨币种汇率不再以 1:1 换算；`convert_amount` 返回 `(0.0, True, "missing_fx")`，零仅为不可换算项的兼容占位，不是该资产真实价值。
- 原 API 数值列和数据库列保持非空、兼容，值只代表已知部分小计；调用方必须检查完整性，不能把这些小计当完整总额。
- 页面不完整总额显示 `--`，呈现具体缺口；缺 FX 的持仓本币价格仍可展示，但换算后的价值/盈亏不可展示为已知。
- Agent 的紧凑响应保留完整性/来源缺口，并将不可用总额、持仓换算金额设为 null，防止把占位小计当投资结论。
- 集中度/行业集中度、含不完整日期的回撤返回 `available=false`、reason=incomplete_valuation；告警记录 degraded 和 data_available=false，而不是风险正常。已知持仓的局部止损条目不用于宣称完整组合已验收。
- 旧回撤记录没有完整性标记且 FX stale 时无法判断是否包含旧 1:1 值，保守不用于完整回撤结论。不完整日期不会变成零权益点。
- 旧快照中的 price_available=false/price_source=missing 或 missing_price 也视为不完整，不会生成假 100% 回撤。快照 API 与风险 API 可以分别回放，页面尊重风险块自身的 available=false，不用另一次成功快照替它判定正常。
- 金额与价格拒绝非有限数值。过期但已知的汇率仍由 fx_stale 标记，不与完全缺失混为一谈。

## 验证边界与兼容性

本轮后端使用假 HTTP/模型传输、假仓库及临时测试库；浏览器使用全 API 拦截的测试页面，不访问真实账户或调用模型。前端沿用现有视觉和动态效果，仅补充数据状态。

Windows 下 21 项旧时区测试调用 POSIX-only time.tzset，无法在当前平台执行；不靠 monkeypatch 伪装时区支持，也不改动其产品日期逻辑。其余定向测试与前端检查结果记录在本地验收日志。

另一个旧 Codex App Server 模拟测试假定宿主支持该后端，但未模拟平台检测；实际未修改的状态服务在 native Windows 明确返回 platform_unsupported，该项不属于 DeepSeek/当前修复的通过项。

没有数据库结构迁移、无新实盘订单路径。尚未部署服务器、未启用真实资讯采集、未做真实供应商/收费模型端到端验收，不能把离线回归当作盈利证明。
