**Goal:** Make the existing Feishu/research work visible and usable through the Web application: manage independent groups/subscriptions, assemble real saved screening results and stored evidence into immutable research drafts, optionally request bounded LLM explanations, review reports, and explicitly test reliable single-target delivery.

**Architecture:** Existing FastAPI/auth/SQLAlchemy/React and configured LLM backend. Add a write-only credential vault, versioned destinations and subscriptions, server-selected evidence aggregation, immutable publications, and a durable manual outbox. Unverified legacy screening history stays a blocked research draft, never becomes a verified current stock recommendation. Existing W1 readiness is not bypassed. Saving, previewing, or approving never sends implicitly.

**Tech Stack:** Python 3.11, FastAPI/Pydantic, SQLAlchemy/SQLite, existing generation backend and Feishu transport, React/TypeScript, pytest/Vitest/Playwright. No new infrastructure or dependency installation.

## Global Constraints

- Read AGENTS.md; preserve all previous dirty changes. No commit/tag/push, deployment, production restart, live keys, real model requests, live market calls, or real Feishu messages during development/testing.
- Tests use injected fake transports/models and temporary databases/configuration. Never initialize against the user's data or load root .env for tests.
- All management APIs require an enabled existing admin authentication system and valid session even when global auth middleware would otherwise allow access. Mutations require same-origin CSRF checks; public unauthenticated configuration is not allowed.
- No browser-supplied `valid`/evidence/date flags may authorize publication. Historical source defects remain explicit. No reranking, changes to strategies, or new markets.
- Secrets are write-only, omitted from response/log/model payload, stored outside ordinary DB as versioned vault references. HTTPS official Feishu host/path only; redirects disabled. Credentials never travel to frontend again after saving.
- New subscriptions and targets default disabled. Manual review only in this slice. Time settings are saved as a planned window, clearly not an active scheduler. Existing single-group notifications remain unchanged.
- Research evidence includes provenance, business date or unknown, real missing information, original risk and actual ranking mode. LLM can explain but cannot invent codes, numbers, citations, targets or guarantees. Deterministic fallback if invalid.
- Explicit test delivery is a fixed branded non-financial message. Formal reports with unresolved core data gaps remain blocked even after review. Human approval cannot turn unknown data into verified facts.
- Durable sending transition precedes HTTP; timeout/disconnect/ambiguous response/crash recovery => delivery_unknown, never automatic second request/text fallback. Success requires platform business code 0. Never fall back to global notification targets.
- UI uses existing components/tokens/navigation; responsive, keyboard accessible, loading/empty/error states, secrets clear after saving. Existing page visual language stays intact.
- Documentation and flat Unreleased changelog updated. Browser evidence under ignored local/audits, not tracked assets.

## Shared contracts and review method

API prefix `/api/v1/research-delivery`, snake_case JSON, explicit TypeScript types (no accidental recursive camel-case conversion). Standard errors have a stable safe code and readable message. Optimistic `version` on destination/subscription writes, stale version => 409. Secret updates increment destination version; old approvals cannot follow new credentials or routes.

Destinations: id, alias, kind=test|strategy|radar|ops, enabled, version, credential_configured, signing_configured, keyword, created_at/updated_at. No URL/token/secret in GET. Subscriptions: id, name, destination_id, strategy_id (actual registered ten A-share strategies), top_n 1..20, llm_mode off|explain_only, planned_time HH:MM (Asia/Shanghai), enabled=false by default, version. Strategy/radar scope expansion is not advertised as implemented.

`GET /capabilities` exposes implemented modes, auth/setup requirements, scheduler_active=false and global sending state. `GET /strategies`, `/destinations`, `/subscriptions`, `/sources`, `/publications`, `/deliveries`. CRUD and report actions specified below. Lists use `{items: [...]}`; details are objects. Stable publication id, content_hash, source_run_id, subscription/destination versions, status, blockers, envelope, rendered content, llm status/usage. Attempt errors contain sanitized classifications, not exception/URL bodies.
