# 数据补全与投研结论一致性

## 已批准需求与全局约束

依据用户确认的上一轮方案，修复概念榜/筹码缺口、整版公告主体混淆、模型正文与风控建议冲突，并增强现有新闻证据。只做人工投研辅助，不新增交易、通知、自动调度或付费订阅。密钥不输出；不提交、不推送；保留既有未提交改动。

先使用现有权限和可验证公开来源。来源不可用时明确缺失，不伪造实时性、筹码或新闻。供应商概念分类不能混作同一官方指数。原始模型判断保留审计，但不是最终行动建议。历史报告不批量改写。

## Task 1: 最终建议一致性

回归复现风控后摘要/买入理由/阶段动作仍激进的反例；使用风控后结构化结果生成明确的最终摘要及动作，保留原始文本在独立审计字段。检查普通分析和 Agent 两条入口、持久化和页面/导出消费。中英韩保持现有支持。

验证：风控及流水线相关测试先失败后通过；已有非触发/否定词测试保持兼容；重复处理不损坏审计记录。

## Task 2: 公告主体及新闻证据

复用现有搜索框架增加单份公司公告证据（若现有依赖支持且可验证），约束证券代码、来源、标题、日期、直接/间接角色。报纸整版及无法证实主体的公告不得进入公司直接事件；保留明确背景标识，合并重复事件。搜索失败不能解释为无风险。

验证：整版 PDF 多公司、其他发行人提到目标银行、直接目标公告、行业新闻、同域普通新闻、日期与重复条目测试；有限公开网络探测。

## Task 3: 概念与筹码补全

复用现有管理器和缓存，补可验证的备用接口；保留来源、获取时间、业务日期、数据质量与失败原因。缓存回退不能伪装今日数据。筹码是估计分布而非真实账户；权限不足、超时、禁用和不支持必须可区分。没有可信免费备用时记录真实缺口，不绕权限。

验证：有效结果、缺日期/过期、单源故障、权限不足、禁用、缓存回退、消费者兼容测试；使用已存配置做有界非交易探测。

## Task 4: 集成与交付

执行受影响回归、编译、必要 Web 构建、独立只读审查；修复重要发现并以回归验证。更新专题文档和 CHANGELOG，安全重启本地服务，验证健康状态和报告可视证据。提供未覆盖项与本轮独立回滚基线。

## 审查关注

自由文本、结构化字段及最终入口是否一致；报纸/公告同域不能一刀切；缓存日期、空结果、权限与真实多源语义；并发请求不能串股票状态；无虚构证据、无密钥泄露、无新增付费依赖。
