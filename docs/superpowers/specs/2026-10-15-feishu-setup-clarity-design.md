# 飞书多群订阅：独立入口与一次保存

用户已于 2026-10-15 确认上一轮方案并要求开始。本文件记录该方案，不重开设计审批。

## 目标与范围

- 通知页默认展示“飞书多群订阅”，旧版字段和测试收进“其他渠道与旧版通知”。不删除、迁移或更改任何现存配置。
- 新增订阅同一表单完成内容类别、已有群或新群连接、Top N、模型解释模式与意向时间；一个保存按钮。
- 新群连接与订阅必须同一数据库事务提交，明确失败不留半个群。网络结果未知提供保存编号和只读核对，不盲目新建。
- 保存成功展示类别→目标群、更新时间、凭据已保存及“自动推送未接通”。成功后清空密钥；只在内存中保留未提交草稿。
- 新增不创建真正的飞书群、不启用目标/订阅、不调用模型、不测试或发送。不新增调度器。
- 保留已有群连接编辑、已绑定订阅编辑、研究预览与人工确认测试。四类未接内容仍明确不可发布。

## 契约

新增 `POST /api/v1/research-delivery/setups`，管理员同源且 HTTPS/实际回环，snake_case。
请求包含 request_id、name、strategy_id、top_n、llm_mode、planned_time；目标二选一：
`new_destination: {alias, webhook_url, signing_secret, keyword}` 或 `destination_id + destination_version`。
返回 `{request_id, destination, subscription}`，公开对象复用原白名单。
`GET /setups/{request_id}` 用同一管理员会话核对；404 表示尚未查询到已提交记录，不保证在途请求已经终止。
新追加 receipt 表保存 request_id、请求摘要和目标/订阅 ID，不存明文凭据；相同请求重复提交返回原记录，改动载荷复用编号返回 409。
复用群要求连接已保存且版本一致；同群同类重复订阅拒绝，但保留旧系统已有数据。
凭据沿用已有 vault；文件写入在事务内完成，数据库回滚可能留下不可达的受保护文件，不清理用户 vault。

## 页面

默认分类列表每类显示“未配置”或群名及保存状态；未配置类别点击直接打开新增订阅表单。工具栏主按钮“新增群订阅”。已有群管理称“群连接”，高级空群登记保留用于 T00 测试。
多群视图不出现旧的“保存配置”或“发送测试”。旧配置有草稿时显示计数/入口，切换不丢草稿；全页离开保护覆盖两套草稿。
错误紧邻表单并以 live region 告知；未知保存锁住草稿，允许只读核对，必要时原编号重提相同请求；不自动发起写请求。

## 验收

临时 SQLite + 假凭据验证真实 API、重建 repository 后持久性、回滚、重复/并发、未知请求恢复、权限/同源/无密钥回显。前端单测与浏览器夹具验证两套入口隔离、一次保存、重载保留、错误保留草稿、两群各自绑定、无外发。桌面和手机截图仅存 local/audits。仅安全重启本地已归属项目进程，不改服务器。
