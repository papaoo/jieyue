# 多资产投研工作台 PRD 与阶段开发规划

版本：v0.2，阶段一实施基线
日期：2026-10-09
状态：用户于 2026-10-09 明确授权在现有框架上先设计并持续开发、集成。阶段一采用石墨方向，工作品牌为“观澜 / Guanlan Research”，集中配置、可后续改名。数据预算、最终商标与上线部署仍未确定。

## 1. 阅读指引与决策摘要

将现有 daily_stock_analysis 演进为以 A 股为核心，覆盖宏观、美股、BTC 与黄金的自有品牌投研工作台。保留现有 FastAPI、React、任务、报告和数据适配能力，不整体重写。

- 第一版优先支持个人研究和内部使用，采用日线/周线频率与有限观察池。
- 研究链路：重要变化 → 原始证据 → 可检验判断 → 候选/策略 → 模拟跟踪 → 复盘。
- 高可信以证据可追溯、历史时点正确、计算可复现、失败可解释衡量；不承诺高收益或保本。
- 开发顺序保持：品牌与工作台 → 宏观及多资产 → 策略验证 → 稳定性与产品化。
- 数据最小连通性验收嵌入第一阶段，避免界面完成后才发现数据无法支持。
- 视觉和交互方案单列于 [UI 设计思路与动效规范](2026-10-09-research-workbench-ui-direction.md)，本地阶段一实施记录见 [开发计划](../plans/2026-10-09-workbench-foundation.md)。

本文中的候选组件、性能数字和验收项是设计建议与目标，不代表已经安装、实现或测试通过。

## 4. 使用场景与范围

### 4.1 核心场景

1. 每日研究：查看重要宏观/市场变化，打开原始来源，了解影响假设和反证。
2. 资产研究：从观察名单进入资产详情，查看价格、事件、关键指标和历史观点。
3. 策略比较：对透明规则进行版本化回测，与基准比较成本后收益、回撤和稳定性。
4. 观点复盘：回看当时实际知道的信息，区分判断错误、数据迟到、数据修订和执行约束。
5. 数据排障：知道一个面板为何为空，能分辨未配置、无权限、接口失败与数据不足。

### 4.2 首轮可交付范围

- 品牌、登录页、导航、总览、已有资产详情与报告阅读的设计升级。
- 数据就绪度面板与有限样本连通性验证；无模型时仍能展示支持的原始数据和规则结果。
- 第二阶段四类资产采用有限观察池；黄金先用 ETF 完成策略路径，现货仅在选定可用来源后加入观察。
- 宏观先选少量可核验指标：国内增长/通胀/信用，海外通胀/政策利率/就业/利率曲线；具体序列随来源验收确定并登记。
- 策略先复用 A 股 ETF 双动量，再增加一个等权或风险预算组合基线。

### 4.3 明确不包含

- 自动下单、托管账户、杠杆/合约交易、收益保证或“稳赚”排行。
- 第一版就做全市场逐笔数据、低延迟交易或全球资产完整覆盖。
- 通过移除版权、伪造行情、隐藏失败、伪造模型置信度实现“自有化”。
- 同时搬入多个完整终端、多个回测引擎或大规模微服务基础设施。
- 未经批准的收费数据订阅、模型调用、邮件/消息外发和计划任务。

## 6. 数据：免费路径、付费边界与接通流程

### 6.1 不能把“页面没有数据”直接归因于收费

现有仓库已经有 Efinance、AKShare、Baostock、Tushare、Yfinance 等适配器。适配器存在不证明当前网络、权限、数据质量都正常。未选择资产、未触发任务、未配置模型、接口失败、历史数据不足，都可能导致不同的空状态。

模型 API、行情 API、新闻搜索 API 和宏观 API 是四种不同能力。没有模型 Key 不等于必须买行情；规则 ETF 轮动不依赖 LLM。项目 `.env` 初始化时没有替用户开通任何第三方账户或付费订阅。

2026-10-09 对当前 `.env` 的必要键做了只读、布尔聚合核验，未输出任何密钥、私有 URL 或股票列表：

| 配置项 | 文件中的状态 |
| --- | --- |
| `STOCK_LIST` | 数量为 0 |
| 模型 Key、模型渠道、外部模型配置、Codex/Ollama 生成配置 | 未配置 |
| 可选行情服务凭据、FXMacroData Key | 未配置 |
| 搜索 Key、自建 Searx 地址 | 未配置 |
| `SCREENING_ENABLED` | true；表示功能开关，不表示已经取得有效行情 |
| 调度、立即执行、机器人、事件监控、自动新闻抓取 | 关闭 |

这不是运行中进程、系统继承变量或数据库自选列表的完整审计，也未对市场接口发请求。不能仅凭文件状态认定全部数据源不可用。实际无需付费 Key 的初始化链路见 `data_provider/base.py` 的数据源管理器。

FXMacroData 官方当前免费无 Key 范围主要为 USD 公布值、日历与目录：最近 90 天、15 分钟延迟、每天 100 次请求。预测值（含 USD）、非 USD、完整历史等需要授权。客户端内有操作名称，不代表账户有调用权。[官方说明](https://fxmacrodata.com/documentation/quickstart)

对上一轮 FRED 候选建议的修正：进一步阅读其当前完整条款后，发现 API 对 AI/ML 开发或训练及存储/缓存/入库的明确限制。官方 MCP 又有独立条款，不能推定它给我们的自建研究系统授予同等权限。因此先暂停把 FRED API 作为本系统默认取数、长期存储和模型输入的方案，取得适用范围澄清或授权后再评估；也可评估 BLS、BEA 等原始发布机构，但每项仍要核验自身条款。这里是工程选型的保守门槛，不代替法律意见。[FRED 完整条款](https://fred.stlouisfed.org/legal/)

FXMacroData 的商业再分发条款也区分面向人阅读的产品输出与原始数据服务，对永久数据仓、公开 raw API/MCP 及可重构数据的 AI 数据集有限制。不能因为买了订阅就默认获得历史仓、公开 API 和无限导出的权利。具体存储期限及用途按所选服务和合同核验。[商业再分发条款](https://fxmacrodata.com/terms/commercial-redistribution)

### 6.3 建议的数据接通验收顺序

1. 先按接口核验读取、缓存、研究、AI 输入、训练及对外展示的许可，再只读核对配置状态；不显示密钥、私有 URL 或账户信息。
2. 不调用模型，使用一只 A 股、一只 ETF、一只美股验证已有行情链；校验代码、单位、最近已收盘日期和来源。
3. 对每个来源分别记录成功、限流、无权限、网络失败、空结果和过期，不能仅记录 HTTP 200。
4. 用无 Key 的 USD 宏观样本验证已有工具；BTC 和新增黄金类型待适配完成后再加入。
5. 只为条款匹配且确有需要的来源申请免费 Key；FRED 保持暂缓，直到当前入库与 AI 用途获得澄清。Key 只存服务端安全配置。
6. 再单独确认模型、搜索与月度成本上限，执行一次有明确用途的解读验收。
7. 最后接 Web 展示；免费源失败时显示缺失/缓存状态，不自动调用付费替代品。

本轮只完成配置状态检查，不执行市场/模型联网验收，不改现有配置；实施时在允许保存的范围内记录样本、时间、实际来源与失败原因。

### 6.4 费用控制

- 默认方案：优先无订阅费的数据路径，允许必要的免费 Key；不是承诺所有功能零成本。
- 分别记录数据订阅费、LLM 输入/输出用量、搜索调用、存储/备份及服务器费用。
- 无预算批准时，新付费能力禁用；不得根据“已经填了 Key”推断允许无限调用。
- 采用按来源限流、获许可的缓存、有限观察池、按需刷新与重试上限，不让所有 Agent 重复取同一份数据。存储权限不明的来源不得自动落库。
- 若未来升级付费数据，先写明补齐的覆盖、延迟、历史和商用权限，再由用户决定是否购买；本文不编造月费报价。

## 7. 可信数据与研究契约

沿用现有 ContextPack 并渐进扩展，以下为拟新增语义，不声称已有同名字段：

| 对象 | 必须表达的语义 |
| --- | --- |
| 资产身份 | 内部稳定 ID、资产类型、交易场所、供应商代码、计价币种、价格单位、时区和日历 |
| 数据记录 | 观测期、源站发布时间、首次采集时间、该版本可得时间、修订 ID、复权/合约口径、原文链接 |

| 研究运行 | 数据快照/引用 ID、规则版本、模型和提示词版本、参数、数据截止、成本与失败状态 |
| 观点 | 事实与推断分开，证据、反证、适用期限、触发/失效条件、后续版本关联 |

历史回放只允许使用当时可获得的版本。缺失历史公布时间时，允许描述性研究，但阻止宣称通过严格时点回测。FRED/ALFRED 的版本日期不能替代精确到分钟的公布时刻；日内事件研究需要额外证明时间精度。

“新鲜”必须依据该来源的发布频率、市场日历和可接受延迟判定，并在来源能力目录登记阈值。不能把所有资产统一设成“24 小时内即正常”，也不能因为本次 HTTP 请求成功就更新为新鲜。

研究快照不等于无条件复制原始数据。只有许可允许的字段和版本才持久化；有限保留期的源执行到期清理，必要时将无法长期复现的运行标明限制。不得为了审计或复盘要求而绕过供应商存储条款。

榜单必须标明市场、证券池、研究周期、数据截止与规则版本。规则风险分、模型自报 confidence、证据完整度和统计胜率是不同概念，不能统一包装成“盈利概率”。

宏观观点不直接转换为交易指令。研究资料和网页内容视为不可信输入：禁止其覆盖系统指令、触发工具权限或泄露配置。来源之间存在冲突时保留冲突，不凭模型语气选一个“事实”。

## 8. 技术路线与组件选择

采用模块化单体，先复用现有 API、任务和存储边界。数据库仍优先现有 SQLite/SQLAlchemy；是否需要额外分析存储或任务设施，依据数据量和并发验收再决定。

- `data_provider/`：来源接入、资产符号映射、限流与数据规范化。
- `src/schemas/`：资产及证据契约的兼容扩展。
- `src/services/`：宏观研究、资产研究、任务编排与来源就绪度。
- `src/core/`：纯计算的因子、策略、指标与可复现验证。
- `api/`：带认证的查询/任务接口，不向浏览器返回密钥。
- `apps/dsa-web/`：品牌、主题、工作台页面和证据展示。

耗时抓取、模型请求和回测不得阻塞页面请求；复用可用的任务链，必要时将重计算隔离到工作进程。MCP 用于受控工具调用，不要求批量行情和回测全部经过模型或 MCP。

| 组件 | 采用建议 | 进入条件 |
| --- | --- | --- |
| 已有 ETF 核心 | 首个策略，优先复用 | CLI/Web 规则语义一致，补样本外和基准口径检查 |
| CCXT / EdgarTools | 第二阶段按需接入 | 最小样本测试、来源条款和依赖兼容通过 |
| skfolio | 第三阶段组合验证候选 | 同币种/可比时点收益矩阵；费用及约束明确，不用样例数据代替生产行情 |
| Macrosynergy | 宏观因子研究候选 | 自备或授权数据转成正确时点面板；示例 NaivePnL 不是成本后交易回测 |
| Apache ECharts | 复杂宏观/风险图表按需引入 | 现有 Recharts 难以满足的图表才使用，控制新增包体 |
| OpenBB ODP | 可选来源网关，不是首版强依赖 | 锁定版本、只选必要 provider；V5 与旧教程的覆盖和许可不同 |
| 完整事件回测引擎 | 后续独立选型 | 真实存在订单级模拟需求后再评估，不在当前环境叠加多个引擎 |

任何第三方库均先审查锁定版本许可证和数据权利，再做隔离验证；不得一次升级全部依赖。保留上游 Git remote 和版权，当前不 commit/tag/push。

## 9. 分阶段开发路线与退出标准

以下为里程碑规划，不是已批准的代码执行清单。不承诺在来源与范围未确认时给出固定工期。

| 阶段 | 工作包 | 依赖 | 退出标准 |
| --- | --- | --- | --- |
| M0 设计确认 | PRD、品牌方向、UI 风格、数据预算、研究侧重 | 用户评审 | 用户明确确认进入哪个阶段；名称未定时不得发布最终品牌 |
| M1 品牌与工作台 | 基线回归、品牌配置、登录/导航/总览/报告升级、动效与空状态、最小数据验收 | M0；现有 API | 页面前后截图；明暗/键盘/减少动效验收；至少一条 A 股/ETF 无付费 Key 行情路径真实成功且内容有效；无新增回归。失败项必须单列，全部取数失败不得验收为可用 |
| M2 宏观与多资产 | 资产身份、来源能力目录、BTC/黄金路径、宏观事件、证据引用、有限观察池 | M1；来源条款与网络可用 | 每类资产至少一个合规有效样本、一个宏观事件全链路；不混代码/单位；重要事实可追溯；缺失数据不会被展示成正常。未接通类别须用户明确缩减范围后才能阶段验收 |
| M3 策略验证 | ETF 策略 Web、一个基线组合、时间顺序验证、观点账本与模拟跟踪 | M2；足够且合规的数据 | 可重跑同快照得同规则结果；费用/滑点/日历/基准说明齐全；样本不足时拒绝夸大统计结论 |
| M4 稳定性与产品化 | 限流重试、作业隔离、监控、成本上限、备份恢复、本地到服务器发布/回滚 | M3；部署确认 | 恢复演练通过；TLS/认证检查通过；实际服务器的数据源连通性单独验收；对外服务另过许可审核 |

每个阶段按“确定性测试 → 最小实现 → 回归 → 人工语义检查 → 验收记录”推进。只对当前阶段写文件级任务和测试细节，避免在未定 UI 与数据条件上冻结整套实现。

## 10. 验收与质量门槛

- 数据：准备有效、缺失、过期、延迟、限流、源间冲突、错误币种、休市和未收盘样本；失败不得污染最后有效缓存。
- 时点：测试修订数据、晚到公告、不同市场日历；不能以前复权曲线和今天的股票池自动声称无未来信息。
- 策略：成本前/后分开；基准同期间同可交易资产；数据不足、退市/停牌、无报价、费用与期货展期按类型处理。
- AI：引用与实际输入一致；有证据不等于结论正确；记录失败和反方依据，不能依赖模型自评作为唯一验收。
- UI：按独立 UI 文档验收；数字不滚动产生不存在的报价，动画不延迟风险提示。
- 安全：请求认证、模型/数据 Key 服务端保存、日志脱敏、导出脱敏、外部资料不具工具授权。
- 前端相关实现：执行现有 lint、build、针对性测试和关键路径浏览器检查；失败逐项说明，不能只凭构建成功交付。
- 后端/API 实现：执行受影响的确定性测试、Schema 兼容检查及相应网络验收；不得把全部来源 mock 掉后声称线上可用。
- 运维：在未接交易账户的前提下验证任务取消、超时、失败重试与恢复；通知仅显式启用。

UI 的 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1 为目标，不是当前测量值。实验室性能检查固定浏览器、视口、数据 fixture 与节流条件；长耗时外部数据/模型完成时间单独报告，不计成页面已经完成研究。

## 11. 重点风险与处理

| 风险 | 处理 |
| --- | --- |
| 免费接口中断、地区不可达或限流 | 逐来源超时与退避；获许可缓存标龄；真实服务器独立测试，不承诺免费 SLA |
| 开源软件与数据使用权混淆 | 建来源许可台账；研究、商用、AI、存储、再分发分别审批，个人用途不自动豁免全部限制 |
| 历史版本不可得、幸存者偏差、大模型记忆未来事件 | 标注研究等级；固定规则时点回测与向前模拟记录互补，不能只展示精选历史胜例 |
| 跨资产价格、币种、日历不一致 | 先定义资产身份和对齐规则；非交易时段只估值不虚构成交 |
| UI 漂亮却没有真实数据 | 从设计稿就包含空/失败/过期状态；演示数据必须持续标明且不入生产存储 |
| 动效损害阅读、可访问性或性能 | 动效分级开关、减少动效、隐藏页面暂停，真实数据即时呈现 |
| 数据订阅/模型费用失控 | 独立预算与调用日志；有限重试；付费源不能自动替换免费源 |
| 上游升级导致品牌修改难维护 | 集中品牌配置、保留技术契约、小步改动，更新前重跑回归 |
| 单机故障或部署回滚失败 | 版本化发布、配置/数据备份和恢复演练；不宣称多机容灾 |

## 12. 评审后下一步

1. 用户选择 UI 方向，并确认是否进入关键页面设计稿评审。
2. 确认品牌名和研究主线；免费优先作为建议，不自动开通任何数据服务。
3. 产出当前阶段的细化 spec、变更文件表与测试任务，再开始实现。
