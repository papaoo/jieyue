# 投研工作台 UI 设计思路与动效规范

版本：v0.2，阶段一设计基线
日期：2026-10-09
关联：[PRD 与阶段开发规划](2026-10-09-multi-asset-research-workbench-design.md)

用户于 2026-10-09 授权在现有框架上先设计并开发。阶段一采用 A 石墨方向和可修改的“观澜”工作品牌，复用现有 Motion；具体实现、验证进度见 [开发计划](../plans/2026-10-09-workbench-foundation.md)。本文件中的其余阶段设计仍是目标，不代表已全部实现。

## 1. 设计目标

阅读为主、比较为辅、操作有反馈的专业投研工作台。让材质、排版、图表和动态交互形成统一体验，同时支持长时间研究、数据缺失和来源失败。

推荐“石墨研究终端”：深色有层次、浅色适合研报阅读，品牌色克制，数字清楚，关键动作有精细动效。UI 默认跟随系统主题并允许切换，不强制所有研究页面永远深色。

## 2. 三个候选方向

| 方案 | 观感 | 动效表达 | 取舍 |
| --- | --- | --- | --- |
| A 石墨研究终端，推荐 | 石墨灰与深海蓝层次、雾白正文、精细边框，局部冷蓝品牌色；等宽数字与舒适中文正文 | 导航标记、详情展开、局部数据更新、图表联动、首屏一次性品牌轮廓光 | 兼顾质感、信息密度和阅读；需要细致做排版与状态，不靠大背景抢视线 |
| B 银白编辑工作台 | 银灰底、白色研究纸面、深色文字与蓝色标注；研究内容更突出 | 章节切换、批注/证据展开、轻量悬停反馈 | 更适合长文、打印和分享；“交易终端感”较弱 |
| C 深蓝态势驾驶舱 | 宏观事件与跨资产图表为中心，较强分区和视觉聚焦 | 事件时间轴联动、情景切换、区域聚焦、有限的入场编排 | 总览有展示力；长文页应降低密度和动效，避免持续视觉疲劳 |

建议以 A 作为全局系统，总览借鉴 C 的信息组织，研报阅读借鉴 B 的排版。颜色、字号、图标、圆角和状态语义仍是一套，不拼成三种互不一致的皮肤。以上是原创设计方向描述，不代表采用某品牌官方组件库。

## 3. 视觉规范提案

### 3.1 材质与颜色

- 石墨底、抬升一层的面板、清楚的细边框形成层级；图表和表格保持实底，保证可读性。
- 品牌区可使用小面积柔光、轻渐变和顶部高光边；模糊仅用于浮层的空间关系，不覆盖数据文字。
- 色彩示意：深色底 `#0F141C`、面板 `#171F2B`、主文字 `#E8EDF4`、品牌蓝 `#6B9FFF`。这是候选色板，实施前逐组合测对比度。
- 浅色主题不是简单反相；重新分配背景、网格线、阴影和次级文字层级。
- 品牌色、涨跌色、风险警告色分别定义；涨跌以正负号/箭头辅助，不能只看红绿。
- 涨跌色约定以 A 股习惯为建议默认，全局可选择；同一用户视图跨市场保持一致，并明确图例，不随资产跳变。

### 3.2 排版与密度

- 中文正文优先可靠系统字体，分析正文 16px、1.6-1.75 行高；表格正文建议 13-14px，辅助文本不小于 12px。
- 价格、百分比、时间使用等宽数字，避免更新时左右抖动；价格小数位按资产精度，不为整齐丢失精度。
- 标题以字重、间距和位置建立层级，不占用大面积研究区域。
- 采用 4/8px 间距基准；输入/按钮/面板圆角分级并统一，不随机组合大圆角和硬边框。
- 核心表格提供舒适/紧凑密度，紧凑模式不缩小触控命中区或隐藏关键信息。
- 首版保留现有图标体系和组件；不为外观同时安装多套设计系统或远程字体 CDN。

## 4. 页面构思

### 4.1 总览

桌面布局示意，不含真实行情，也不是最终设计稿：

```text
┌──────────────┬──────────────────────────────────────────┐
│ 自有品牌     │ 页面标题 / 时间范围 / 数据状态 / 主题      │
│ 总览         ├──────────────────────────┬───────────────┤
│ 宏观         │ A 股 / 美股 / BTC / 黄金状态摘要          │
│ 资产研究     ├──────────────────────────┼───────────────┤
│ 策略实验     │ 重要变化与跨资产比较图    │ 即将公布事件  │
│ 组合与复盘   │ 点击事件可定位证据        │ 数据异常提示  │
│ 数据与设置   ├──────────────────────────┼───────────────┤
│              │ 观察名单 / 候选与变化     │ 研究任务状态  │
└──────────────┴──────────────────────────┴───────────────┘
```

主区突出变化和比较，右栏承接事件、来源异常及任务。未接入资产显示“尚未接入”与后续动作，不放虚构涨跌幅或假新闻。市场状态摘要不是跨资产收益排名。

### 4.2 宏观与资产研究

- 宏观事件卡：公布值、前值/修订、预期来源、观测期、公布时刻、数据质量。
- 选择事件后，同步定位资产图表上的实际时间标记；不同市场休市/开市状态同时可见。
- 资产页以价格/事件为主区，右侧证据抽屉显示原文、引用段落、时间和缺失说明。
- “事实 / 推断 / 待验证”用文字标签区分；相互矛盾的证据并列呈现。
- 宏观数据日期精度不足时，不显示具有误导性的分钟级对齐动画。

### 4.3 策略与研报

- 策略页采用参数区、结果区、交易/风险记录三层；提交研究任务是明确动作，修改参数不偷偷调用模型或付费数据。
- 结果展示净值、回撤、基准、费用和样本外区间，不把一个高分放在所有证据之前。
- 报告页使用更舒展的行距和宽度，证据可展开，图表可查精确数据。
- 自有内容体现在研究问题、模板、策略规则和复盘记录；第三方原文与版权声明不冒充我们的原创内容。

## 5. 动效清单

目标是“动作精致、状态可理解”，用户操作始终优先。动画可被中断，不等待动画结束才允许点击。

| 编号 | 场景与触发 | 标准动效 | 减少动效 / 风险约束 |
| --- | --- | --- | --- |
| MOT-01 | 登录品牌首次显示 | 轮廓光或轻高光扫过一次，300-400ms，随品牌出现结束 | 静态标志；不循环，不抢表单焦点 |
| MOT-02 | 用户切换导航 | 选中标记过渡 140-180ms；主内容淡入，最多 4px 位移，180-220ms | 无位移、即时或短淡入；轮询不得重播入场动画 |
| MOT-03 | 打开证据/筛选抽屉 | 180-240ms 轻滑入和遮罩淡入，关闭稍快 | 直接展开；键盘焦点移入、关闭后回到触发按钮 |
| MOT-04 | 图表选择事件或时间范围 | 十字线、事件标记和关联面板同步更新；选中边界 120-180ms | 即时定位；不将两套历史曲线插值成不存在的价格轨迹 |
| MOT-05 | 收到更新且数值真实变化 | 先即时显示新值，再局部底色/描边轻提示 200-300ms | 静态变化标识；禁止数字从 0 滚到新价、禁止伪造中间报价 |
| MOT-06 | 后端任务进入新阶段 | 图标/文字过渡 120-160ms，用户可打开任务详情 | 即时文字；仅显示真实阶段，无总进度就不编百分比 |
| MOT-07 | 首次加载超过 300ms | 与最终布局同尺寸的骨架，低对比 shimmer | 静态骨架；失败/超时立即退出骨架，显示原因与重试 |
| MOT-08 | 点击按钮、聚焦可交互卡片 | 边框/颜色 80-120ms，小幅按压反馈 | 保留清楚焦点；不让数据卡片追随鼠标倾斜或漂移 |

登录品牌区可以有独特视觉记忆点；研究正文和数据表不播放持续粒子、扫光、视差或自动轮播。市场“实时”标记只能来自实际数据状态，不能用动画制造实时感。

## 6. 动效开关与实现边界

- 提供“跟随系统 / 减少动效 / 关闭动效”；跟随系统为默认。系统启用减少动效时，不以站内标准模式强行覆盖。
- 使用现有 Motion 与 CSS，优先 `transform` / `opacity`；颜色提示限定小区域，不持续重绘全屏。
- 全局减少动效之外，CSS、Recharts 和未来 ECharts 动画也必须单独遵守设置。不能只关闭 Motion 就称全部完成。
- 隐藏标签页停止装饰动画；返回页面先核验新鲜度，再显示变化。动画自身不得引发网络刷新。
- 大列表采用分页/必要时虚拟化；图表按路由按需加载，字体和资源有本地回退。
- 首版不引入 WebGL、粒子引擎、3D 地球或第二套动画库；若以后为宏观地理数据确有表达需要，再单独评审。
- Motion 官方支持全局减少动效与按组件处理：[可访问性说明](https://motion.dev/docs/react-accessibility)。具体写法以锁定版本 API 验证为准。

## 7. 数据状态也是设计的一部分

以下维度分别展示，不压成一个含糊的绿色“正常”：

| 维度 | 例子 | 展示原则 |
| --- | --- | --- |
| 接入/权限 | 未接入、缺少 Key、无权限、已配置 | “已配置”不等于已请求成功；Key 存在不代表订阅有效 |
| 请求/内容 | 加载中、成功、空结果、失败、部分返回 | 空结果不是价格为 0；错误要给可执行的下一步 |
| 时效 | 新鲜、延迟、过期、未知；是否已收盘 | 列出数据时刻和时区；刷新页面不重写源数据时间 |
| 来源属性 | 原始观测、估计、缓存、演示 | 缓存可新鲜也可过期；演示必须持久标明且不得进入生产记录 |
| 任务 | 排队、抓取、分析、完成、部分完成、失败、取消 | 只显示后端确认状态，不伪造进度 |

浏览器标题、登录页、安全提示和报告标题同步品牌策略。当前登录页写死的 `DSA-V3-TLS` 文案不能作为实际 HTTPS 证明；后续应按真实连接状态表述，不保留虚构安全协议品牌。

## 8. 设计验收

以下目标均待实现后测量，当前并未通过验收：

- 视口：375px、768px、1366px、1920px；200% 缩放可操作。小屏只允许明确标注的表格容器横向滚动，不让整个页面溢出。
- 主题：深浅两套分别验证，普通文本对比度至少 4.5:1；不能靠低对比灰字制造质感。
- 键盘：导航、筛选、抽屉、图表替代表格可访问，焦点清楚；关闭抽屉后位置可恢复。
- 动效：系统减少动效、站内关闭、后台标签页、快速反复切换都要覆盖；数据先正确可读，再呈现反馈。
- 状态：总览、宏观/资产、策略、报告四类页面至少包含成功、加载、未接入/空、失败/过期状态稿。
- 图表：单位、时间、币种、图例、来源可见；不把数据平滑装饰成实际观测，不填补未说明的缺口。
- 性能：固定 fixture 和环境记录 LCP/布局偏移、交互延迟及动画长任务；外部接口和模型延迟单独报告。
- 回归：登录、现有路由、历史报告、设置保存不被视觉升级破坏；截图保存在忽略目录作为验收证据。

## 9. 审批门槛

请先选择 A、B 或 C，或指定它们的组合倾向。选定风格后，下一步是关键页面设计稿评审，而不是立即铺开全部功能。

最终名称/Logo、页面稿、动效强度及当前阶段范围得到确认后，才进入 UI 编码。尚未选定名称时，设计稿只使用明确的工作标题，不对外发布。

本方案采用 UI/UX 规范中的可访问性、状态反馈、动效与排版原则；本机 skill 配套检索脚本缺失，未声称使用自动生成的设计系统，也没有为本次文档安装依赖。
