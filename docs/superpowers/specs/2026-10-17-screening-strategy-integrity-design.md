# A 股策略证据一致性修复设计

日期：2026-10-17

状态：用户于 2026-10-17 确认实施，并追加多起点、多区间回测及向各策略群发送结果的授权。

## 1. 目标与边界

让现有 10 个 A 股筛选器的实际输入、条件、评分、覆盖范围与页面/飞书中的声明一致。解决“程序能跑，但某些策略的关键逻辑没有真正执行”的问题。

这不是一轮根据短期盈亏调参的优化。此前 57 条候选的外部收益评估存在时间锚定问题，不能据此停用某个策略、调权重或选择新阈值。修复通过意味着实现符合契约，不意味着已经证明盈利能力。

保留策略 ID、已有群订阅、凭据、历史冻结结果；不增加自动交易，不修改 ETF/海外策略，不部署、不提交或推送 Git，不开启新的模型调用或付费数据服务。最新授权允许在修复和验证之后，向已配置的对应策略群各发送一次清晰标记的回测总结；不重发旧的日常策略卡片。

## 2. 两种可行路径

1. **推荐：修计算链路，同时纠正策略声明和明确的条件矛盾。** 新规则单独版本化；关键证据缺失时显示未完成评估，不发布成完整策略结果。结果数量可能减少，计算时间可能增加。
2. 只修连接/覆盖并披露限制，保留原筛选条件。这能降低变更范围，但仍不能把“量比允许 1.5”叫已确认缩量，也不能把“距离前高 -1%”叫已突破。

不建议在此时换用另一套开源策略，也不建议针对那 57 条记录优化收益。前者扩大范围，后者会把错误日期口径和小样本偏好固化进规则。

## 3. 已核实的根因

## 4. 第一阶段：修复现有计算契约

本阶段是第一份实施计划的范围。后续完整财务模型和绩效观察属于独立阶段，不能因第一阶段验收通过而宣称全部完成。

### 4.1 统一依赖与缺失处理

- 增加统一的策略计算依赖解析入口，综合硬过滤、启用的评分因子、风险与行业控制需要的字段。
- `list_strategies`、`preview_strategy`、`screen`、正式采集使用同一解析结果，不各写一套分支。
- A 股内置新版策略中，使用 momentum/reversal/stability 的日线分支必须获得有效日线特征；不能因为硬过滤未引用日线，就静默使用快照版本。
- 缺失值、权限不足、超时、合法零值、因历史不足而不适用分别记录。合法的 0 不视为缺失；缺失不填成 0 或中性 50 分后宣称证据齐全。
- 数据依赖齐全但没有股票通过条件是“完成，0 候选”；依赖没齐是“未完成评估”。两者在 API、页面和消息状态上分开。
- 原始响应、字段来源、单位、业务日期、采集时点、计算规则版本进入冻结输入。使用财报的发布日期不能晚于决策截止时间。
- 现有自定义策略的兼容行为保留并明确标记；不能让历史保存的结果在展示时按新版逻辑重新计算。

### 4.2 候选范围与采集预算分离

- 策略应评估范围是通过快照硬过滤的全部候选，不再是快照排名前 100 名。
- 100 可以保留为一次工作批次的大小，不能作为最终策略范围。
- 多策略日线需求合并去重；同一代码、业务日期、价格口径及计算版本只计算一次。
- 采集支持按批记录进度、错误和剩余候选。预算耗尽或服务中断后保留未评估列表，重试不得丢失分母或把已失败候选当成不存在。
- 计算完成后，对全部符合日线条件的候选统一评分，再执行风险/集中度处理并取 Top N。不能对每个批次单独计算百分位分数再直接拼接。
- 明确的新股历史不足等可验证的不适用原因单独报告；数据源故障、未知停牌状态不能伪装成合理剔除。
- 全范围尚未完成时可以在系统中查看进度和局部诊断，但不发布“完整策略 Top N”。
- 第一阶段只复用同业务日、同参数、同证据哈希的采集结果，解决续跑重拉，不改变跨日证据语义。持久缓存保留真实原始采集时间。跨日增量缓存另行实现原始证据与当日派生证据的关联，并同步升级发布端日期契约；禁止把旧响应时间改成今天。
- 不默认发起全市场历史网络回填；先离线验证、测量请求预算，再进行有上限的小范围在线验收。

### 4.3 行业信息与分散控制

- 用户追加确认：实时选股与回测统一迁移到有历史公开记录的行业标准，并标为新策略版本。本条替代最初仅传递当前 `stock_basic.industry` 的方案。
- 采用 `capco_major_v1`：中国上市公司协会已公开报告的门类字母加两位大类代码。实时与回放共同使用同一适配器、身份字段和分组逻辑；原供应商行业名称可保留作旧报告展示，不再作为新版分组的备用真值，也不使用 LLM 猜测替代。
- 历史信号只使用信号日之前已公开的报告，保守从发布后的首个交易日启用，不倒填到报告期末。保存报告、发布日期、原始哈希和北交所别名映射；具体来源及覆盖预检见 `2026-10-17-historical-data-sources.md`。
- 对不足 61 个交易日的新股，以及在适用报告编制截止日后上市、尚无公开分类的新股，采用明确且有证据的版本化不适用规则，保留排除计数。老股不明原因缺项、未知 ST 或代码映射失败仍阻断评估，不能从分母静默删除。
- 第一阶段恢复现有“集中度软惩罚”的真实执行，并明确显示它不是每行业最多 N 只的硬上限。不会擅自把研究观察名单改成组合配置。
- 同业集中度统计在完整评分池上检查，最终报告列明已识别行业覆盖率；无法执行时返回明确状态，不再静默成功。
- 新闻、板块叙事和 LLM 摘要仍在筛选之后处理，不能反过来改变冻结排名或掩盖数据缺口。

### 4.4 10 个策略的修复范围

| 策略 ID | 第一阶段修复 | 本阶段不能声称的能力 |
| --- | --- | --- |
| `balanced_alpha` | 接齐声明的评分依赖；输出有效权重及因子覆盖；说明是规则多因子筛选 | 经统计训练或验证的 alpha；多因子彼此独立 |
| `blue_chip_income` | 保留全市场 `daily_basic.dv_ttm` 并验证口径；股息证据不全时不称收益质量已确认 | 派息连续性、现金流覆盖或未来股息得到保证 |
| `capital_heat` | 日线参与评分；将“资金确认”改为准确的“量价活跃”；真实资金流尚未纳入时明确区分 | 成交活跃等于主力净买入 |
| `dual_low` | 明确为股票低 PE、低 PB，接齐评分依赖 | 可转债双低或估值陷阱已排除 |
| `low_volatility_quality` | 全范围计算真实波动、回撤与 ATR，修复行业输入 | 财务质量已确认或低波溢价已验证 |
| `momentum_quality` | 日线实际执行，趋势证据及其是否满足进入结果；没有确认条件就不能称趋势确认 | 只有当日涨跌幅就证明趋势；财务质量已核实 |
| `oversold_reversal` | 接入 RSI/区间涨跌等已实现日线特征；当前没有反转触发时只能标记超跌观察 | 单日下跌就是反转成功；自动创造一套未经评审的抄底规则 |
| `quality_value` | 接齐评分依赖，准确说明低估值/交易稳定性代理；财务证据与代理分数分开展示 | PE/PB 低就说明盈利与现金流质量好 |
| `shrink_pullback` | 缩量要求当日量严格小于前 20 日均量；补充实际回落与均线距离收敛条件，保留原趋势/风险边界 | 静态距 MA20 较近就是已完成回踩；缩量证明“洗盘而非出货” |
| `volume_breakout` | 确认突破要求收盘严格高于前 20 日最高价；原始/衍生价格精度参与比较，不以四舍五入后的展示数判定；整理天数配置与文案统一 | 距离前高 -1% 就是已经突破 |

具体技术语义：

- 缩量使用 `当日成交量 / 前 20 个有效日线成交量均值 < 1`，不含当日均量。不得通过把 1.5 改成 1.0 的包含边界比较仍让等量样本通过。
- 回落要求 `当日收盘 < 前一有效交易日收盘`，且 `当日收盘/当日 MA20 - 1` 小于前一交易日对应距离；原有均线多头、站上 MA20 和波动/回撤限制继续保留。这是有限的“趋势内缩量回落”定义，不声称识别全部回踩序列或支撑反弹。
- 突破使用 `当日收盘 > max(此前 20 根有效日线 high)`，保留原有量能、阳线、均线和风险限制。
- 整理天数沿用现有配置 8 天并同步解释为 8 天，不因提示词写了 10 天就偷偷改规则。
- 超跌反转与财务质量的完整新规则不在本阶段凭空补阈值；先消除未执行逻辑和过度声明。下一阶段需要单独确定经济含义和评价口径。

### 4.5 分数和标签

- `screen_score`/`final_score` 保持规则排序分，不转成胜率；解释明确它依赖同批候选池，不能跨日/跨策略直接比较。
- 第一阶段不根据亏损样本调因子权重，也不删除 `tech_weight` 的自定义配置兼容分支。
- 对尚未接通的板块/主题因子明确记录未参与证据；不再把中性占位值当已观测因子。本阶段不得以“修复”为名静默重分配权重：若一个新版策略声明必须使用该因子，缺失时评估未完成；若保留可选占位分支，结果必须属于受限研究模式，不能发布成完整版本。
- `value_quality`、`capital_confirmed` 等仅由已有规则分数触发的标签改为与实际计算相符的名称；旧存档标签继续能解释为旧版语义。
- 记录技术信号被哪些评分项使用；多策略共现只是重复命中，不作为独立证据数量或置信概率。

### 4.6 版本与发布

- 受影响的内置规则提升版本；冻结输入包含策略版本、规则摘要哈希、有效因子权重和覆盖统计。
- 不改策略 ID，订阅继续指向原类别；页面展示新版的准确描述。
- 正式发布端核对版本、声明依赖与覆盖结果；不再靠 `technical_limit <= 100` 判断有效性。
- 旧报告保持原样，旧策略的重新渲染不等于新版重新计算。禁止修改过去的信号时间以改善评估结果。
- 实施与测试不发送消息；生产自动任务切换在本地验收说明后处理，不以测试名义触发推送。

## 5. 后续阶段，不混称已完成

### 第二阶段：真正的财务/资金证据入模

目前已存在的 Tushare 适配可提供部分 ROE、利润同比、同报告期利润/经营现金流、股息及资金流，但当前 Top N 补资料接口的预算不适合全候选调用。

后续复用这些适配，按策略需要的数据类别做跨策略去重与缓存，在筛选前冻结必要事实。财务以公告日和报告期区分，保留各字段的实际/修订披露日期 `f_ann_date`，不能在合并后只留下较早的 `ann_date`。已有营收、利润和经营现金流属于披露期累计口径，不能冒充 TTM。只有公告日期而没有发布时间/修订版本时，不能声称历史数据严格符合当时可知范围。

分红区分预案与已实施，供应商 `dv_ttm` 与按已实施事件计算的 365 天现金额保持独立口径。资金流明确供应商统计定义；现有“最近 5/10 条”在用作“5/10 交易日”条件前，必须经过交易日历对齐及缺失检查。金融与非金融企业不能生搬同一经营现金流/负债比阈值。

第一阶段只先保留成本低的股息字段、对齐声明与数据状态。只有新的财务筛选规则、覆盖与缺失处理得到单独验收后，才把“质量确认”“资金流确认”重新引入正式策略。

### 第三阶段：正式候选的前瞻观察闭环

- 数据源为正式计算/发布候选，不把旧 `screening_runs` 与新策略版本混为一谈。
- 保存业务日期、实际可获得时刻、实际发布时刻、策略版本、排名及来源结果。绝不用价格相近推断信号日期。
- 以信号可获得之后的下一可交易时点为起点；价格涨跌的描述性观察与考虑停牌、涨跌停、费用的模拟交易评价分开。
- 固定多个观察期限，未到期记录保持待观察；重复推送不重复增加独立样本，跨策略同股同日显式标记相关。
- 宽基、行业/风格匹配对照同时报告；行业匹配基准不可用时报告缺失，不用任意单个行业代替所有股票。
- 不用今天的上市公司名单及行业分类冒充历史时点全集，不承诺现有行情权限已经足够完整历史回测。

## 6. 第一阶段验收标准

1. 构造仅评分依赖日线、硬过滤不依赖日线的策略，验证目录、预览、正式采集与计算都声明并使用日线；缺失时不能正常完成。
2. 候选超过 100 时，第 101 名及以后参与最终完整评估；分批处理结果与一次完整离线计算一致，批次顺序不改变结果。
3. 批次故障、预算耗尽和重试后，候选分母及错误名单保持；未完成结果不能过正式发布校验。
4. 缩量：比值 0.99 满足量条件，1.0 和 1.5 不满足；未发生回落/距离收敛不能标记回踩。
5. 突破：低于或等于前高不通过；高于前高且其他条件满足才通过；当日 high 不进入前高窗口。
6. 相同行情、不同且有证据的行业分类应改变实际集中度处理；行业缺失返回明确未评估状态，不伪装成完成。
7. 相同 PE/PB 不得凭空产生财务质量/资金净流入已确认标签；零股息与缺股息分开。
8. 日线未来数据、错码、错误业务日、缺复权因子仍被拒绝；缓存复用保留来源日期，不绕过这些守卫。
9. 已发布报告与订阅不被修改；运行测试不能触发真实 LLM、数据抓取或飞书发送。
10. 更新 `docs/feishu-research-delivery.md`、相关数据/策略说明和 `docs/CHANGELOG.md`；新增配置同步 `.env.example`。不扩大 README。

主要复用测试：`test_screening_compute_only.py`、`test_builtin_screening_engine.py`、`test_research_delivery_dependencies.py`、`test_research_delivery_preview.py`、`test_research_delivery_readiness.py`、`test_research_delivery_live_collector.py`、`test_research_delivery_formal.py`、`test_research_delivery_brief.py` 及相关 API/前端契约测试。

## 7. 实施和回滚约束

当前工作树有大量已有修改。实施前记录本轮文件基线，不能用 `git reset` 或覆盖整个文件的方式回滚。回滚只撤销本轮精确补丁，保留原有功能和用户数据。

离线确定性测试先行；有限在线验收只验证数据可获得性和计算链路，不生成绩效结论。未验证完整网络采集时必须明确说明。正式切换前检查现有服务是否热加载，避免未验收的策略被自动任务读取。

## 8. 自审结论

- 已区分工程修复、规则定义纠正、需要进一步设计的财务模型与前瞻评价，不把三者混为一次“收益优化”。
- 已明确缺数据与无候选的不同状态、全范围与每批预算的不同含义。
- 没有按已失真的 57 条收益结果调参，没有新增资金/交易授权。
- 用户已确认，实施计划同时加入历史回放的数据准入、固定回测设置和一次性回测结果推送；关键历史数据无法核实时输出相应未完成原因，不发布伪回测收益。
